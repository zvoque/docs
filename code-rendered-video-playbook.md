# Code-Rendered Video Playbook

> Part of a frontier/craft reference set for steering AI tools, editors, and developers past the default. Default reach: try to make a precise, on-brand, typographic, or data-driven video with a diffusion model — and watch it mangle the text, approximate the brand color, and invent the numbers. Use the **trap** on each entry to avoid the cliché.

A working reference for building motion graphics and video **programmatically** — code → frames → mp4 — the deterministic lane that complements generative/diffusion video. Covers: **the core pattern**, **Remotion**, **HyperFrames**, **other tools** (Motion Canvas, Revideo, Editly, FFmpeg), **the in-code animation toolkit**, and **video-specific concerns** (fps, aspect, brand tokens, data-driven, captions, audio sync, performance). Each entry: what it is, when to reach for it, and the trap to avoid.

This is the *code-render* half of AI video; its complement is generative/diffusion video — [`ai-video-generation-playbook.md`](ai-video-generation-playbook.md) (Higgsfield, Veo, Kling, etc.). The two are a **hybrid**: generate b-roll and backgrounds with diffusion, composite deterministic type, UI, data, and captions on top with code. Siblings: [`video-editing-taxonomy.md`](video-editing-taxonomy.md), [`motion-graphics-taxonomy.md`](motion-graphics-taxonomy.md), [`video-audio-taxonomy.md`](video-audio-taxonomy.md), [`video-preproduction-taxonomy.md`](video-preproduction-taxonomy.md). GSAP technique is covered in depth in the repo's existing [`gsap-playbook.md`](gsap-playbook.md) and only cross-referenced here.

Compiled June 2026. Tool versions, pricing, and licenses move fast and are flagged as time-sensitive — re-verify before committing a pipeline.

## How to use this doc

- **Code-render is the deterministic lane; diffusion is the generative lane.** They don't compete so much as divide the frame: code for anything that must be *exact* (type, brand color, data, UI, captions), diffusion for anything *imagined* (photoreal scenes, natural human motion, b-roll). Most real pipelines are hybrid.
- **The whole game is `time = frame / fps`.** Every frame is a pure function of its frame index. The renderer *seeks* to a timestamp and screenshots — it doesn't play in real time and record. That's the source of both the superpower (determinism, testability, parallelism) and the #1 footgun (anything driven by the wall clock flickers).
- **Determinism is why this is the agent lane.** An LLM emits markup or React; the renderer is a pure function; the same input gives the same bytes. That makes the output testable, version-controllable, and trivially fan-out-able — and makes templated, data-driven, personalized-at-scale video possible.
- **Pick the tool by who's authoring.** A React team → Remotion. An LLM/agent authoring from a prompt → HyperFrames (plain HTML). A hand-crafted explainer with a GUI → Motion Canvas. Assembling existing clips → Editly/FFmpeg.
- **Re-verify the licensing and pricing.** Remotion is source-available (paid above 3 employees); HyperFrames is Apache-2.0; Motion Canvas is MIT (with a possible GPL move); GSAP is now free. These changed within the last year — confirm before you build on them.

# 1. The core pattern

### Render code frame-by-frame, stitch with FFmpeg
Express each video frame as a pure function of time: `frame → pixels`. A scene is authored as markup or code (HTML/CSS/JS, React, Canvas, SVG, WebGL); a headless browser (**Puppeteer** or **Playwright** driving headless Chromium) is *seeked* to a precise timestamp, the page is painted, and a screenshot is captured as one image; repeat for every frame `0 … durationInFrames-1`; then **FFmpeg** muxes the image sequence plus audio into an mp4. This is the architecture under Remotion, HyperFrames, Motion Canvas, Revideo, and Editly alike. **Reach for it** whenever the video must be exact, repeatable, or generated by an agent. **Trap:** see the determinism footgun below.

### The deterministic advantage
Time is quantized to `frame`, and `time = frame / fps`. Because the renderer *seeks* rather than letting a wall clock run, **same input → same output, byte-stable**. Animation isn't "played and recorded" (which drops/duplicates frames under load) — it's *sampled*. This buys: reproducible, regression-testable video; frame-accurate timing regardless of render speed; and trivial parallelization (different machines render different frame ranges of the same deterministic timeline and the chunks concatenate seamlessly — exactly how Remotion Lambda works). Determinism + parametrization is what makes it ideal for **agents** (an LLM emits markup, the renderer is a pure function) and for **templated / data-driven / personalized-at-scale** video. **Reach for it** for CI-tested pipelines and 10,000-variant batches. **Trap:** you only get determinism if *every* animation is a function of the frame — see below.

### When code-render beats diffusion
- **Exact, legible type** — diffusion still mangles long/precise text; code renders real fonts pixel-perfect.
- **Precise brand color & assets** — exact hex, logos, fonts, layout. Diffusion approximates; code is exact.
- **Data viz / charts / counters / dashboards** — bound to real numbers that must be *correct*, not plausible.
- **Templated, personalized, repeatable** — "10,000 variants, one per user/listing," year-in-review, programmatic-SEO video, automated ad matrices.
- **Deterministic / testable / versionable** pipelines; lower-thirds, captions, kinetic text, UI walkthroughs, explainers.

### When it cannot (reach for diffusion instead)
- **Photoreal scenes** — real-world imagery, lighting, materials, b-roll.
- **Natural human motion / talking-head avatars** — gait, micro-expressions, lip-sync to arbitrary speech.
- **"Imagine something that doesn't exist"** — anything where you want the model to *invent* imagery.
- The 2026 pattern is **hybrid**: diffusion for b-roll/backgrounds, code for the deterministic type/UI/data/captions on top. **Trap:** forcing diffusion to render a precise dashboard, or forcing code to "imagine" a photoreal forest — each fails at the other's job.

### The determinism footgun (the #1 trap)
Anything driven by the *real* clock breaks, because the renderer captures a *seeked* moment, not a played one: `Date.now()`, raw CSS transitions / `requestAnimationFrame`, autoplaying `<video>`, un-seeded `Math.random`. Every animation must be a function of the frame, and randomness must be seeded. **Secondary traps:** headless ≠ your machine (fonts must be embedded/loaded or they silently fall back; GPU/WebGL behaves differently; you must `await` async readiness — images, fonts, data — before capture or you screenshot a half-painted frame); color/encoding (`-pix_fmt yuv420p` is required for broad mp4 compatibility — forget it and QuickTime/iOS won't play the file); and speed (capturing N frames through a browser is inherently slow — the price of determinism).

### The canonical FFmpeg stitch (the primitive under everything)
```bash
# frames → mp4 (note pix_fmt for compatibility; -framerate before -i sets input fps)
ffmpeg -framerate 30 -i frame-%05d.png -c:v libx264 -crf 18 -pix_fmt yuv420p out.mp4
# add audio, trim to shortest
ffmpeg -i out.mp4 -i voice.wav -c:v copy -c:a aac -shortest final.mp4
```

# 2. Remotion

### What it is
A framework for making **videos as React components** — the dominant, best-documented player in this space. Every frame is a render of your component tree at a given frame index; change what you draw per frame and you get animation. It ships a Studio (live preview/scrubbing), an embeddable `<Player>`, a CLI/Node renderer (headless Chromium + bundled FFmpeg), and **Remotion Lambda** for distributed cloud rendering. **Reach for it** when your team writes React and you want the richest ecosystem, an embeddable interactive player, and turnkey horizontally-scaled rendering. **Trap:** the licensing threshold and the React-all-the-way authoring cost (below).

### Core model & APIs
- **`useCurrentFrame()`** — the current frame number (0-indexed, ends at `durationInFrames-1`). *The* hook; the docs are emphatic — **"Always animate using `useCurrentFrame()`"**, never CSS transitions or the wall clock, or you get flicker.
- **`<Composition>`** — registers a renderable video, binding a component to `width`, `height`, `durationInFrames`, `fps`. `useVideoConfig()` reads them back. `time = frame / fps`.
- **`interpolate(input, inputRange, outputRange, opts)`** — maps a frame across ranges, e.g. `interpolate(frame, [0,60], [0,1], {extrapolateRight: 'clamp'})`; supports `extrapolateLeft/Right` and an `easing` option (with the `Easing` module — bezier, in/out/inOut).
- **`spring({frame, fps, config, ...})`** — a deterministic physics spring; `config = {mass, damping, stiffness, overshootClamping}`; returns 0→1 (may overshoot unless clamped).
- **`<Sequence from={n} durationInFrames={d}>`** — the timeline primitive: time-shifts children so a child's `useCurrentFrame()` reads 0 at `from`, mounting/unmounting only within its window. **`<Series>`** lays sequences back-to-back.
- **`<AbsoluteFill>`, `<Img>`, `<Audio>`, `<OffthreadVideo>`** (the frame-accurate way to embed video *during render* — not `<Video>`), **`staticFile()`** (reference `/public`), **`delayRender()` / `continueRender()`** (block capture until async data/fonts/images are ready — the official fix for the half-painted-frame trap), **`<Still>`** (single-frame image output).
- **Captions & transitions:** **`@remotion/captions`** provides `parseSrt`, `serializeSrt`, and **`createTikTokStyleCaptions()`** → word-by-word karaoke "pages" with per-token `fromMs/toMs`; transcription via **`@remotion/install-whisper-cpp`** or **`@remotion/whisper-web`**. **`@remotion/transitions`** handles slide/fade/wipe between sequences.

### Parametrized / data-driven (the killer feature)
A composition takes typed React props. `defaultProps` set Studio defaults; **input props** inject at render time (CLI `--props='{...}'` or a JSON file, or `inputProps` in `renderMedia()` / `renderMediaOnLambda()`). One composition + a row of data = one personalized video; loop the dataset = thousands. **`@remotion/zod-types`** types and validates props and gives you Studio form controls for free. **Reach for it** for personalized-at-scale video. **Trap:** unvalidated data breaks frames at scale — validate/clamp with zod and snapshot-test representative rows.

### Server-side & Lambda rendering
On your own infra: `@remotion/bundler` (`bundle()`) + `@remotion/renderer` (`selectComposition()`, `renderMedia()`). At scale: **Remotion Lambda** (`renderMediaOnLambda()`) — a main function resolves the composition, then **fans the frame range across many renderer Lambdas** that each render a chunk and stream it back to be stitched (concurrency = `frameCount / framesPerLambda`, ≥20 frames/Lambda, capped at 200 functions). Cloud infra (AWS/GCP) is billed separately. **Reach for it** for high-throughput batches. **Trap:** the deterministic-parallelism only works because every frame is pure — a wall-clock leak desyncs the chunks.

### Licensing (verify before shipping — the catch)
Remotion is **source-available, NOT open source** (a custom "Remotion License"). **Free** for individuals, non-profits, evaluation, and for-profit companies with **≤3 employees**; cloud rendering allowed if self-hosted. **Companies >3 employees need a paid Company License** (remotion.pro) — as of 2026, roughly **$25/developer seat/month**, minimum spend ~$100/month or $1000/year, Enterprise minimum ~$500/month; cloud infra billed on top. **Trap:** easy to build on for free as a small team, then trip the >3-employee threshold in production — budget for it and confirm current terms at remotion.pro/license. *(Pricing changed within the last year — time-sensitive.)*

### Other traps
It's **React all the way** — an agent must emit a correct React+Remotion project (bundler, hooks rules, `useCurrentFrame` discipline), heavier than emitting plain HTML (the explicit motivation for HyperFrames). And the `<Video>` vs `<OffthreadVideo>` footgun — use `<OffthreadVideo>` for embedded footage during render or it desyncs.

# 3. HyperFrames

Two distinct things share the name; conflating them is the #1 error. Both are HeyGen.

### 3a. HyperFrames — the open-source engine (`github.com/heygen-com/hyperframes`)
An **open-source, HTML-to-video rendering engine built for AI agents.** You author a composition as **plain HTML/CSS/JS** with timing in **`data-*` attributes** (no React, no proprietary timeline); the engine drives headless Chrome via Puppeteer, seeks and captures each frame, and FFmpeg encodes frames + audio into a **deterministic mp4**. **License: Apache 2.0** — no usage caps, no telemetry, no forced cloud, no API key for local use. **Requirements: Node 22+ and FFmpeg.** Released ~May 2026. **The thesis:** LLMs write HTML/CSS fluently and After-Effects/React-animation poorly — so give agents a video primitive in the language they're best at: **HTML in, deterministic mp4 out.** It is positioned as the *deterministic complement* to HeyGen's generative avatar video. **Reach for it** when an **agent** authors the video from a prompt, when you want deterministic CI-testable mp4s with **no React build step and no commercial-license gate**, or when you already have HTML/CSS design assets to retarget. **Trap:** newer and smaller than Remotion (thinner docs, six packages, API may still shift); non-seekable JS animations need a "frame adapter" or they desync; same headless-Chrome realities (fonts, async readiness, GPU variance) as [§1](#1-the-core-pattern); and the name collision with 3b.

Composition shape:
```html
<div data-composition-id="launch" data-start="0" data-width="1920" data-height="1080">
  <video data-start="0" data-duration="6" data-track-index="0" src="intro.mp4"></video>
  <h1    data-start="1" data-duration="4" data-track-index="1">Launch day</h1>
  <audio data-start="0" data-duration="6" data-track-index="2" src="music.wav"></audio>
</div>
```
Animation support: GSAP, CSS animations, Lottie, Three.js, Anime.js, WAAPI — plus **"frame adapters"** that drive each library's internal clock to the exact frame time (the mechanism that defeats the wall-clock trap). CLI: `npx hyperframes init` / `preview` / `render`. Agent install: **`npx skills add heygen-com/hyperframes`** (Claude Code, Cursor, Gemini, Codex). Packages: `hyperframes` (CLI), `@hyperframes/core` (types, parsers, linter, runtime), `@hyperframes/engine` (Puppeteer + FFmpeg), `@hyperframes/producer` (full pipeline), `@hyperframes/studio` (browser editor), `@hyperframes/aws-lambda` (distributed). **`frame.md`** is a documented concept for retargeting web design tokens *for video* — the brand-token bridge (see [§6](#6-video-specific-concerns)).

### 3b. HyperFrames — the hosted product (`hyperframes.net` / `.app` / `hyperframes.heygen.com`)
A **hosted SaaS** that turns websites/docs/PDFs/product knowledge → demos, onboarding videos, explainers ("source-to-video"), pairing a cloud Studio ("edit videos by vibe-coding," AI-assisted composition) with the same open-source engine as the render core. **Reach for it** for the managed, GUI/agent front-end when you don't want to self-host. **Trap:** don't point an agent at the hosted SaaS when you meant the library, or vice-versa.

> **Disambiguation rule.** Open-source engine = `github.com/heygen-com/hyperframes`, Apache-2.0, local CLI, Node 22 + FFmpeg, you own rendering. Hosted product = `hyperframes.net`/`.app`/`.heygen.com`, account/cloud/Studio, source-to-video + vibe-coding, billed. Treat only `github.com/heygen-com/hyperframes` and `*.heygen.com` as authoritative — parked look-alike domains exist.

# 4. Other tools

### Motion Canvas (`motioncanvas.io`)
TypeScript **animation-as-code with a real-time visual editor** (Vite-powered). You write **generator functions** and `yield*` animation tweens in sequence (imperative, procedural timeline) — you describe durations and easings, and the editor scrubs/previews live. Canvas-based renderer (single `<canvas>`). **License: MIT.** **Reach for it** for hand-crafted **explainers, educational/technical animation, voice-over-synced visualizations** (the "manim, but TypeScript" niche) where you want fine motion control plus a GUI. **Trap:** the generator/`yield*` model has a learning curve; canvas-only (no DOM layout); weaker for high-throughput data-driven batch rendering than Remotion/Revideo; and there's an open maintainer discussion about **possibly relicensing to GPL** — verify the license on the version you pin.

### Revideo (`docs.re.video`) → Midrender
A fork of Motion Canvas that adds what it lacks for automation: **headless/server-side rendering**, a **library-first Node API** (`renderVideo()`), **audio support**, **parameterized templates**, and parallel rendering — built to mass-produce shorts/ads/demos from code. **Reach for it** for Motion-Canvas authoring plus a real render API. **Trap (current status):** the team has **pivoted to *Midrender*** (`midrender.com`) — a visual motion-graphics editor on Revideo's engine with AI-assisted editing and MCP (Claude Code/Cursor) support — and "recent changes have not yet been upstreamed," so the OSS repo may lag. `re.video` now redirects to `midrender.com/revideo`. Pin versions and check upstream freshness before betting a pipeline on it.

### Editly (`github.com/mifi/editly`)
A **declarative FFmpeg NLE** for Node: a JSON/JS spec of clips, images, titles, audio, and transitions → an edited video. Not a per-frame animation engine — a timeline/assembly + transitions layer over FFmpeg (with some GL transitions). **Reach for it** to programmatically **assemble/concatenate** existing clips and images with crossfades and music, slideshow-style. **Trap:** intermittent maintenance and native deps (canvas/GL) that can be painful to install; not the tool for bespoke kinetic typography or data viz.

### Raw FFmpeg — the universal substrate
Not a framework — the **encode/stitch/composite/concat** engine under all of the above, and a standalone tool you'll still drop to directly. Core jobs: image-sequence → mp4 (`-pix_fmt yuv420p`), concatenation (concat demuxer or filter), overlays/lower-thirds (`-filter_complex "[0][1]overlay=x:y"`), audio mux/normalize (`loudnorm`), format/codec/aspect transforms, burned-in subtitles (`subtitles=foo.srt`). **Reach for it** for the final stitch, batch transforms, overlays, and anything you don't need a browser to draw. **Trap:** flag order matters (`-framerate`/`-ss` before vs. after `-i`), `-pix_fmt yuv420p` is mandatory for broad playback, and complex `filter_complex` graphs get unreadable — keep them generated and version-controlled.

# 5. The in-code animation toolkit

What actually moves the pixels inside any of the above.

### GSAP (GreenSock) — timelines & tweens
The industry-standard JS animation engine: `gsap.timeline()` sequences tweens with relative/absolute positioning and **`stagger`**; rich easing; plugins (ScrollTrigger, SplitText, MorphSVG, Flip). **Major current fact:** after Webflow acquired GreenSock (Oct 2024), **GSAP became 100% free for all use including commercial (~April 2025)** — all former paid Club plugins are now free; GreenSock ships official AI skills. **In code-render:** drive a GSAP timeline by **seeking it to the frame's time** (`tl.seek(frame/fps)` / `tl.time(t)` / `tl.progress(p)`) instead of autoplaying — the "frame adapter" pattern HyperFrames uses. **Reach for it** for timelines, staggers, and kinetic type inside any renderer. **Trap:** GSAP defaults to wall-clock playback; if you don't *seek* per frame you get flicker/desync. **Cross-reference the repo's [`gsap-playbook.md`](gsap-playbook.md) for GSAP depth.**

### Lottie — After Effects → JSON → render
Workflow: animate in After Effects → export via Bodymovin/LottieFiles → **JSON** (or `.lottie`/dotLottie, ~50–70% smaller). `lottie-web` plays it via SVG/Canvas, crisp at any resolution, and is **programmatically seekable** (`goToAndStop(frame)`) — exactly how you make it deterministic in a frame renderer (Remotion has `@remotion/lottie`). **Reach for it** for designer-authored vector motion (icons, branded loaders) you want pixel-faithful without re-coding. **Trap:** the SVG renderer doesn't support every AE feature (some effects/expressions don't translate) — validate the headless render and prefer `goToAndStop` over autoplay.

### Three.js / WebGL — 3D in the browser
Real 3D scenes, cameras, lights, GLTF models, shaders. In a deterministic renderer, **advance the scene to the frame's time and call `renderer.render()` per frame** — don't run an animation loop. **Reach for it** for 3D product shots, logo reveals, shader/particle effects. **Trap:** GPU/WebGL in **headless Chromium** is the fragile part — driver/SwiftShader differences, missing GPU on CI, and per-frame determinism require seeding any time/random and disabling the rAF loop; test the *headless* output, not the local preview.

### SVG, Canvas & CSS
**SVG animation** (SMIL / CSS / JS) — vector line-draws, path morphs, data-bound charts; prefer driving it via JS/GSAP with explicit per-frame seeking (SMIL isn't cleanly frame-seekable headless). **Canvas 2D** — immediate-mode drawing for generative/particle/data-viz visuals; you own everything and must redraw deterministically from `frame`, never accumulate state. **CSS keyframes/transitions** — fine for the web, **dangerous in code-render** because they're wall-clock; only use them pinned to the frame (`animation-delay: -{t}s; animation-play-state: paused`). **Trap:** CSS transitions are the canonical determinism footgun — Remotion's docs literally warn against them.

### Easing in code
Two families: **cubic-bézier** (`cubic-bezier()`, named eases, Remotion `Easing.bezier()`, GSAP `power`/`expo`/`elastic`/`back`) — pure functions of progress, perfectly deterministic; and **springs** (physics — Remotion `spring()`, GSAP inertia) — deterministic *when seeded by frame*, with natural overshoot/settle. **Trap:** mixing easing *systems* across layers (CSS ease vs. GSAP power vs. spring) makes motion feel incoherent — pick a token set and reuse it.

# 6. Video-specific concerns

The things web animation doesn't have to think about but video does.

### fps, duration & frame-accurate timing
The whole game: **`time = frame / fps`**, frames `0 … durationInFrames-1`. Author everything as a function of `frame` (or seek every library to `frame/fps`). Common fps: 24 (film), 30 (web/social default), 60 (smooth UI). Duration is set in **frames**, not seconds (6s @ 30fps = 180 frames). **Trap:** fps mismatches between your timeline, embedded assets, and the FFmpeg output cause judder/dropped frames — pin one fps end-to-end.

### Resolution & aspect
Targets: 16:9 1920×1080 (landscape), 9:16 1080×1920 (Reels/TikTok/Shorts), 1:1 1080×1080 (feed), 4:5 1080×1350 (IG portrait). Best practice: author **aspect-agnostic** — one composition + `width`/`height` props + responsive layout — so one template emits every ratio. **Trap:** odd pixel dimensions break `yuv420p` H.264 (needs even width/height); naive scaling distorts — letterbox or crop deliberately.

### Safe areas
Keep key content inside margins: platform UI eats the bottom ~15–20% and right edge on 9:16; broadcast title-safe ≈ inner 90%, action-safe ≈ inner 93%. **Trap:** text/logos to the true edge get clipped by player UI — bake safe-area insets into the template (HyperFrames' `frame.md` / Remotion props are the place to encode them).

### Brand-token / theme-driven templating
Drive type, color, spacing, and logos from a **token set** (design tokens / theme object / CSS variables) so one template re-skins per brand. HyperFrames formalizes this as **`frame.md`** (web tokens retargeted for video); Remotion does it via typed props + `@remotion/zod-types` for editable, validated controls. **Trap:** web tokens don't transfer 1:1 — video needs larger minimum type sizes (legible at thumbnail scale), motion tokens (durations/easings) the web doesn't define, and safe-area-aware spacing.

### Data-driven & personalized-at-scale
The core economic win: composition + dataset → N videos. Inject per-render **input props** (Remotion `inputProps`/`--props`; HyperFrames data files), loop rows, fan out to Lambda/serverless. Use cases: per-user year-in-review, per-listing real-estate/e-comm videos, automated ad-variant matrices, programmatic-SEO video. **Trap:** unvalidated data → broken frames at scale (text overflow, missing images, NaN in charts) — validate/clamp inputs (zod), set fallbacks, and snapshot-test representative rows before a 10k-render batch.

### Captions, lower-thirds & charts in code
Captions: word-level karaoke via `@remotion/captions` + `createTikTokStyleCaptions` (pages/tokens with `fromMs/toMs`), transcription via whisper; or burn SRT/ASS with FFmpeg `subtitles=`. Lower-thirds: positioned animated DOM/SVG layers (`<AbsoluteFill>` + spring-in). Charts: render a real chart lib (D3, Recharts, Chart.js, Canvas) **bound to data and seeked per frame** for animated reveals — exact numbers, exact brand colors (the headline reason to code-render). **Trap:** caption timing must be ms-accurate to the audio (off by a frame reads as lag) — generate timings from forced alignment/whisper, don't hand-place.

### Performance of headless capture
Capturing N frames through a browser is the bottleneck. Mitigations: **parallelize frame ranges** across machines/Lambdas (determinism makes chunks concatenate seamlessly); reuse a warm browser/page; cap concurrency to CPU/GPU; pre-resolve all async assets once; prefer `OffthreadVideo`-style frame extraction over playing embedded video; encode with a sane CRF (18–23), not lossless. **Trap:** memory leaks across thousands of frames (un-disposed Three.js/canvas contexts, growing DOM) crash long renders — dispose per frame and/or chunk the job.

### Audio sync in code-rendered video
Audio is **not** captured from the browser — it's composed separately and **muxed by FFmpeg** at the end, each track placed at its start time (Remotion `<Audio startFrom/>`; HyperFrames `data-start`/`data-duration`; FFmpeg `-itsoffset`/`adelay`/`amix`). Because video is sampled by frame and audio is a continuous track, they only line up if **both reference the same `frame/fps` clock**. **Trap:** sample-rate/fps drift slowly desyncs A/V over a long video — lock the audio sample rate, derive cue points from `frame/fps`, normalize loudness (FFmpeg `loudnorm` per [`video-audio-taxonomy.md`](video-audio-taxonomy.md)), and verify sync on a *long* render, not a 5-second test.

# 8. The code-rendered trap index

- **Wall-clock animation** — `Date.now()`, CSS transitions, autoplay video, raw `requestAnimationFrame`, un-seeded random. The #1 cause of flicker/desync; everything must be a function of the frame.
- **The half-painted frame** — capturing before fonts/images/data have loaded. Await readiness (`delayRender`/`continueRender`) first.
- **Missing `-pix_fmt yuv420p`** — an mp4 that won't play on QuickTime/iOS.
- **Odd pixel dimensions** — breaks `yuv420p` H.264 encoding; keep width/height even.
- **Forcing diffusion to be exact** — a precise dashboard or brand-typographic title handed to a diffusion model that mangles it. Code-render it.
- **Forcing code to imagine** — a photoreal forest or natural human motion hand-coded. Generate it.
- **The Remotion license surprise** — building for free as a small team, then tripping the >3-employee threshold in production with no budget for it.
- **The HyperFrames name collision** — pointing an agent at the hosted SaaS when you meant the OSS engine (or a parked look-alike domain).
- **A/V drift over length** — verified on a 5-second test, broken over five minutes because audio and video reference different clocks.
- **The 10k-render that breaks at row 4,000** — unvalidated data, no snapshot test, a memory leak that crashes the batch.

---

## Quick decision checklist

1. **Code or diffuse?** Exact type/brand/data/UI → code. Photoreal/human/imagined → diffuse. Most real videos are hybrid — do both and composite.
2. **Pick the tool by author** — React team → Remotion; agent/LLM → HyperFrames; GUI explainer → Motion Canvas; assemble clips → Editly/FFmpeg.
3. **Make every animation a function of the frame.** Seek GSAP/Lottie/Three to `frame/fps`; never trust the wall clock; seed all randomness.
4. **Await readiness before capture.** Fonts, images, data — block the frame until they're loaded.
5. **Author aspect-agnostic** with brand tokens + safe-area insets, so one template emits 16:9 / 9:16 / 1:1 / 4:5.
6. **Validate data before a batch.** Clamp/fallback inputs, snapshot-test representative rows, then fan out.
7. **Mux audio to the same `frame/fps` clock** and verify sync on a long render.
8. **Encode for compatibility** — `-pix_fmt yuv420p`, even dimensions, sane CRF.
9. **Re-verify licenses & pricing** (Remotion paid >3 staff; HyperFrames Apache-2.0; Motion Canvas MIT/maybe-GPL; GSAP free) before committing.
